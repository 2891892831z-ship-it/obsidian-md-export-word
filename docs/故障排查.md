# 故障排查

## 只显示“正在导出”，没有 Word

1. 等待右上角最终成功或失败提示；
2. 运行 `Check Word export runtime`；
3. 查看实时进度窗口最后停留的阶段；
4. 若失败，查看 Markdown 同目录的 `原文件名-导出失败.log.txt`；
5. 确认文件不是只读，且 Word 没有占用同名输出；
6. 用兼容模式排除 Zotero citekey 阻断；
7. 保留失败提示最后几行。

## 运行时安装失败

常见原因：

- GitHub Release 尚未发布；
- Release 标签与插件版本不一致；
- Release 缺少当前系统对应的运行时 ZIP；
- GitHub 被网络或代理拦截；
- Python 版本低于 3.10；
- `pip` 无法访问 PyPI；
- Windows 杀毒软件阻止 PowerShell、Pandoc 或新建虚拟环境；
- macOS 上 Python 版本不足，或运行时文件失去执行权限。

处理：

```text
MD Export Word: Install or repair Word export runtime
MD Export Word: Check Word export runtime
```

发布者应同时检查 Release 中是否有：

```text
main.js
manifest.json
styles.css
md-export-word-runtime-windows-x64.zip
md-export-word-runtime-macos-arm64.zip
md-export-word-runtime-macos-x64.zip
SHA256SUMS-windows-x64.txt
SHA256SUMS-macos-arm64.txt
SHA256SUMS-macos-x64.txt
```

插件只下载当前系统的一份运行时。若自动识别错误，打开插件设置查看“运行时
平台”；普通用户应保持“自动检测”。

## macOS 提示权限不足或无法运行

先执行：

```text
MD Export Word: Install or repair Word export runtime
MD Export Word: Check Word export runtime
```

安装程序会自动为 macOS 脚本、Pandoc 和 pandoc-crossref 设置执行权限。
如果仍失败：

1. 在终端运行 `uname -m`，确认 `arm64` 或 `x86_64`；
2. 在插件设置确认运行时平台与该结果一致；
3. 运行 `python3 --version`，确认 Python 3.10+；
4. Apple Silicon 原生 Obsidian 应使用 `macos-arm64`；
5. Intel Obsidian/Rosetta 才使用 `macos-x64`；
6. 查看“系统设置 → 隐私与安全性”是否明确阻止了下载的可执行文件；
7. 重新安装运行时后再次自检。

不要用 `sudo` 运行 Obsidian。插件只需要在自己的插件目录和 Markdown 输出
目录内读写。

## macOS 安装时提示找不到 Python

macOS 不保证预装可用于本项目的 Python。安装
[python.org 的 macOS universal2 安装包](https://www.python.org/downloads/macos/)，
重新打开 Obsidian，再执行“Install or repair Word export runtime”。

项目不会向系统 Python 安装 `lxml`，而是在
`.obsidian/plugins/md-export-word/runtime/.venv` 内创建私有环境。

## 这台电脑仍找不到 LibreOffice

LibreOffice 不参与 Markdown→Word 的核心导出。它只用于某些自动渲染或 PDF
预览。导出运行时自检不要求 `soffice`。

## Zotero 无法连接

- 启动 Zotero；
- 确认 Better BibTeX 已启用；
- 等待启动完成后重试；
- 严格模式需要所有 citekey；
- 临时查看文档可选兼容模式。

## 图片模糊

判断顺序：

1. 查看原图像素尺寸；
2. 检查 Markdown 是否引用缩略图、剪贴板预览或压缩后的图床 URL；
3. 直接下载图床文件，与原图比较文件大小和像素；
4. 优先改用本地原图；
5. 不要把低像素图在 Word 中放大。

PicGo 通常上传收到的文件；如果剪贴板中已经是预览位图，上传的也会是低分辨率
版本。最稳妥方法是从原图文件路径插入或上传，而不是从软件界面截图复制。

## Word 打开时询问“是否更新域”

这通常说明模板或文档中存在 Word 外部链接域。处理方法：

1. 对话框选择“否”；
2. 在 Word 中检查“文件 → 信息 → 编辑指向文件的链接”；
3. 清除模板中的外部 `INCLUDETEXT`、`LINK` 等域；
4. 另存为新的干净模板；
5. 重新导出。

Zotero 引文刷新应在 Word 的 Zotero 选项卡执行。

## 两个题目

Markdown frontmatter 的 `title` 和正文的 `# 标题` 内容相同会造成重复。只保留
一个题目来源。导出器会在自检中报告明显重复，但不会擅自删除论文内容。

## 公式出现空表或多列

- 检查公式 Markdown 前后是否有空表格语法；
- 每个公式只保留一个 `{#eq:id}`；
- 不要手工建立公式编号表；
- 不要在公式标签后加表格竖线；
- 用最小示例复现并查看日志中的公式表结构检查。

## 注释字号或对齐不一致

确认注释以以下形式开头且未带列表符号：

```text
注：
Note:
Notes:
```

中英文都会应用注释样式。表内普通正文不会因包含 “note” 单词而自动变成注释。

## 严格模式误报英文 Fig./Table 图表题

`1.4.0` 曾把严格模式的图表题校验误写成只接受中文 `图1/表1`，导致英文期刊
常用的 `Fig. 1`、`Figure 1` 和 `Table 1` 在 Word 已生成后被错误删除。
该问题与 macOS、图片路径或 Zotero 无关，已在 `1.4.1` 修复。

Markdown 中以下写法均可保留：

```yaml
figureTitle: Fig.
tableTitle: Table
figPrefix: Fig.
tblPrefix: Table
```

严格模式继续严格检查 Zotero citekey，但不会再限制图表题使用中文还是英文。

## 提交问题前需要提供

- 插件版本；
- Obsidian 版本；
- 操作系统版本与 CPU 架构；
- 自检输出；
- `导出失败.log.txt`；
- 最小化 Markdown 示例；
- 问题位置截图；
- 若可提供，去除敏感内容后的 Word；
- 不要提交 Zotero API Key、私人仓库 Token 或未公开论文数据。
