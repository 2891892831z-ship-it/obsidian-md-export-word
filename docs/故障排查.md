# 故障排查

## 只显示“正在导出”，没有 Word

1. 等待右上角最终成功或失败提示；
2. 运行 `Check Word export runtime`；
3. 查看实时进度窗口最后停留的阶段；
4. 若失败，查看 Markdown 同目录的 `原文件名-导出失败.log.txt`；
5. 确认文件不是只读，且 Word 没有占用同名输出；
6. 用兼容模式排除 Zotero citekey 阻断；
7. 保留失败提示最后几行。

## 运行时安装失败

常见原因：

- GitHub Release 尚未发布；
- Release 标签与插件版本不一致；
- Release 缺少当前系统对应的运行时 ZIP；
- GitHub 被网络或代理拦截；
- Python 版本低于 3.10；
- `pip` 无法访问 PyPI；
- Windows 杀毒软件阻止 PowerShell、Pandoc 或新建虚拟环境；
- macOS 上 Python 版本不足，或运行时文件失去执行权限。

处理：

```text
MD Export Word: Install or repair Word export runtime
MD Export Word: Check Word export runtime
```

发布者应同时检查 Release 中是否有：

```text
main.js
manifest.json
styles.css
md-export-word-runtime-windows-x64.zip
md-export-word-runtime-macos-arm64.zip
md-export-word-runtime-macos-x64.zip
SHA256SUMS-windows-x64.txt
SHA256SUMS-macos-arm64.txt
SHA256SUMS-macos-x64.txt
```

插件只下载当前系统的一份运行时。若自动识别错误，打开插件设置查看“运行时
平台”；普通用户应保持“自动检测”。

### 一直显示“正在下载”

运行时 ZIP 约为 34-73 MB，访问 GitHub 较慢时可能需要几分钟。`1.4.6`
开始，安装提示会持续显示当前阶段和累计用时；同一插件实例中的重复命令、
重复点击、导出和 Zotero 引文处理会复用正在进行的安装，不会再次下载；
插件目录原子锁也会阻止热重载或多个窗口同时安装。

`1.5.1` 起，运行时 ZIP 通过 Obsidian 网络层按 4 MB 分块请求，可继承操作
系统代理，并显示百分比、速度和预计剩余时间。若浏览器使用的是浏览器扩展
代理而不是系统代理，浏览器能打开 GitHub 并不代表 Obsidian 也能访问；此时
应把代理配置到操作系统或确保 Obsidian 能使用同一代理。

首个兼容请求的最长等待时间为 15 分钟，后续每个 4 MB 分块为 5 分钟；这是
单次请求的总时限，不是网络空闲时限。超时后不会自动并发重试，下载窗口会
提供手动重试。处理顺序：

1. 确认浏览器能打开当前版本的 GitHub Release；
2. 完全退出并重新打开 Obsidian；
3. 只执行一次“Install or repair Word export runtime”；
4. 安装完成前不要更新 BRAT 或关闭 Obsidian；
5. 完成后执行“Check Word export runtime”。

Obsidian 当前公开网络接口不提供底层请求的强制中止。点击“取消下载”会立即
终止安装流程、删除临时文件并忽略迟到响应；服务器正常支持 Range 时，后台
最多只会完成当前 4 MB 分块。若代理忽略 Range，当前系统请求可能继续到网络
层自行结束，但其响应不会写入文件或触发安装。

### macOS 报临时 ZIP 不存在

`1.4.5` 及更早版本在安装被重复触发时可能共用同一个临时 ZIP，其中一个
流程清理文件后，另一个流程会出现：

```text
ditto: .../.runtime-download-macos-x64.zip: No such file or directory
```

这不表示 Release 缺少 macOS ZIP。先通过 BRAT 更新到 `1.4.6`，重启
Obsidian，再执行一次运行时安装。`1.4.6` 会复用在途任务，并为每次安装使用
独立临时工作区。

## macOS 提示权限不足或无法运行

先执行：

```text
MD Export Word: Install or repair Word export runtime
MD Export Word: Check Word export runtime
```

安装程序会自动为 macOS 脚本、Pandoc 和 pandoc-crossref 设置执行权限。
如果仍失败：

1. 在终端运行 `uname -m`，确认 `arm64` 或 `x86_64`；
2. 在插件设置确认运行时平台与该结果一致；
3. 运行 `python3 --version`，确认 Python 3.10+；
4. Apple Silicon 原生 Obsidian 应使用 `macos-arm64`；
5. Intel Obsidian/Rosetta 才使用 `macos-x64`；
6. 查看“系统设置 → 隐私与安全性”是否明确阻止了下载的可执行文件；
7. 重新安装运行时后再次自检。

不要用 `sudo` 运行 Obsidian。插件只需要在自己的插件目录和 Markdown 输出
目录内读写。

## macOS 安装时提示找不到 Python

macOS 不保证预装可用于本项目的 Python。安装
[python.org 的 macOS universal2 安装包](https://www.python.org/downloads/macos/)，
重新打开 Obsidian，再执行“Install or repair Word export runtime”。

项目不会向系统 Python 安装 `lxml`，而是在
`.obsidian/plugins/md-export-word/runtime/.venv` 内创建私有环境。

## 这台电脑仍找不到 LibreOffice

LibreOffice 不参与 Markdown→Word 的核心导出。它只用于某些自动渲染或 PDF
预览。导出运行时自检不要求 `soffice`。

## Zotero 无法连接

- 启动 Zotero；
- 确认 Better BibTeX 已启用；
- 等待启动完成后重试；
- 严格模式需要所有 citekey；
- 临时查看文档可选兼容模式。

## 英文 Fig. 或 Table 图表题被判定为格式错误

先确认插件和运行时均已更新到 1.4.1 或更高版本，然后检查 frontmatter：

```yaml
figureTitle: Fig.
tableTitle: Table
figPrefix: Fig.
tblPrefix: Table
```

从 1.4.1 开始，严格模式与兼容模式都支持标准中英文题名前缀，并读取
`figureTitle`、`tableTitle` 的自定义值。若仍失败，日志会列出实际题名和允许
的题名前缀，可据此检查不可见字符、缺失编号或空题名。

## 图片模糊

判断顺序：

1. 查看原图像素尺寸；
2. 检查 Markdown 是否引用缩略图、剪贴板预览或压缩后的图床 URL；
3. 直接下载图床文件，与原图比较文件大小和像素；
4. 优先改用本地原图；
5. 不要把低像素图在 Word 中放大。

PicGo 通常上传收到的文件；如果剪贴板中已经是预览位图，上传的也会是低分辨率
版本。最稳妥方法是从原图文件路径插入或上传，而不是从软件界面截图复制。

## Word 打开时询问“是否更新域”

这通常说明模板或文档中存在 Word 外部链接域。处理方法：

1. 对话框选择“否”；
2. 在 Word 中检查“文件 → 信息 → 编辑指向文件的链接”；
3. 清除模板中的外部 `INCLUDETEXT`、`LINK` 等域；
4. 另存为新的干净模板；
5. 重新导出。

Zotero 引文刷新应在 Word 的 Zotero 选项卡执行。

## 两个题目

Markdown frontmatter 的 `title` 和正文的 `# 标题` 内容相同会造成重复。只保留
一个题目来源。导出器会在自检中报告明显重复，但不会擅自删除论文内容。

## 公式出现空表或多列

- 检查公式 Markdown 前后是否有空表格语法；
- 每个公式只保留一个 `{#eq:id}`；
- 不要手工建立公式编号表；
- 不要在公式标签后加表格竖线；
- 用最小示例复现并查看日志中的公式表结构检查。

## 注释字号或对齐不一致

确认注释以以下形式开头且未带列表符号：

```text
注：
Note:
Notes:
```

中英文都会应用注释样式。表内普通正文不会因包含 “note” 单词而自动变成注释。

## 严格模式误报英文 Fig./Table 图表题

`1.4.0` 曾把严格模式的图表题校验误写成只接受中文 `图1/表1`，导致英文期刊
常用的 `Fig. 1`、`Figure 1` 和 `Table 1` 在 Word 已生成后被错误删除。
该问题与 macOS、图片路径或 Zotero 无关，已在 `1.4.1` 修复。

Markdown 中以下写法均可保留：

```yaml
figureTitle: Fig.
tableTitle: Table
figPrefix: Fig.
tblPrefix: Table
```

严格模式继续严格检查 Zotero citekey，但不会再限制图表题使用中文还是英文。

## Zotero Refresh 后正文引文由蓝色变成黑色

这不是导出失败。Zotero Refresh 会重写动态域的显示文本，并可能覆盖直接
颜色格式。请先保存 Word，再回到对应 Markdown，通过命令面板运行
“Reapply blue Zotero citations to exported Word”。插件会生成新的蓝色引文
副本，保留 Zotero 域且不覆盖源 Word。

## 提交问题前需要提供

- 插件版本；
- Obsidian 版本；
- 操作系统版本与 CPU 架构；
- 自检输出；
- `导出失败.log.txt`；
- 最小化 Markdown 示例；
- 问题位置截图；
- 若可提供，去除敏感内容后的 Word；
- 不要提交 Zotero API Key、私人仓库 Token 或未公开论文数据。
