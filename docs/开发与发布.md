# 开发与发布

本项目以 Obsidian 官方 sample plugin 的构建结构为基础，并补充运行时打包、
Windows 回归测试和 BRAT Release 资产。

## 仓库准备

```powershell
git clone https://github.com/<owner>/obsidian-md-export-word.git
Set-Location obsidian-md-export-word
npm install
npm run check
npm run build
```

开发模式：

```powershell
npm run dev
```

如需直接在测试知识库中开发，可把仓库克隆到：

```text
<测试知识库>\.obsidian\plugins\md-export-word
```

不要使用正式论文库作为唯一开发环境。

## 目录职责

```text
src/                    Obsidian 插件源码
runtime/                可发布运行时的文本脚本与模板
scripts/                校验、版本和打包脚本
docs/                   用户与开发文档
.github/workflows/      CI 和 Release
main.js                 Obsidian 实际加载的编译产物
manifest.json           插件清单
versions.json           插件/Obsidian 兼容关系
```

## 本地构建运行时

本仓库不跟踪大型 `.exe`。在已有匹配二进制时执行：

```powershell
.\scripts\build-runtime.ps1 `
  -PandocExe "C:\path\to\pandoc.exe" `
  -CrossrefExe "C:\path\to\pandoc-crossref.exe"
```

生成：

```text
dist\md-export-word-runtime-windows.zip
dist\SHA256SUMS.txt
```

构建脚本会：

- 拒绝把输出写到仓库外；
- 复制脚本和模板到临时目录；
- 加入两个匹配的二进制；
- 为运行时文件计算 SHA-256；
- 把哈希写入 `runtime-manifest.json`；
- 生成运行时 ZIP 和总校验文件；
- 清理临时目录。

## 版本规则

以下位置的版本必须一致：

```text
package.json
manifest.json
runtime/runtime-manifest.json
versions.json
Git tag
GitHub Release name
```

升级补丁版本：

```powershell
npm version patch
```

Obsidian Release 标签必须是纯版本号，例如：

```text
1.3.1
```

不要写成：

```text
v1.3.1
```

## 发布流程

1. 更新 `CHANGELOG.md`；
2. `npm version patch|minor|major`；
3. `npm run check`；
4. `npm run build`；
5. 在测试知识库完成迁移检查清单；
6. 提交版本改动；
7. 推送提交和标签；
8. GitHub Actions 自动创建 Draft Release；
9. 检查 Release 资产和 SHA-256；
10. 下载 Release 到干净测试库，用 BRAT 安装；
11. 验收后发布 Draft。

Release 工作流使用 Windows runner：

- 构建带实际 `GITHUB_REPOSITORY` 的 `main.js`；
- 下载 Pandoc 3.8.2.1；
- 下载为 Pandoc 3.8.2.1 构建的 pandoc-crossref v0.3.22a；
- 执行 Python 导出烟雾测试；
- 构建运行时 ZIP；
- 附加插件与运行时资产。

## 第一次推送到 GitHub

```powershell
git remote add origin https://github.com/<owner>/obsidian-md-export-word.git
git branch -M main
git push -u origin main
git tag 1.3.0
git push origin 1.3.0
```

推送和创建公开 Release 会改变外部状态，应在确认仓库公开范围、许可证和论文
模板可公开后再执行。

## 发布前隐私检查

```powershell
rg -n "C:\\Users|API[_ -]?Key|token|secret|OB知识宝库|Zotero" .
git status --short
git diff --check
```

还要人工确认：

- 模板内无作者隐私、修订记录或外部文件链接；
- 示例 Markdown 不含未公开论文内容；
- 没有 Zotero API Key 或私人仓库 Token；
- 没有用户名和绝对路径；
- Word 模板属性中不含不希望公开的信息。

## BRAT 验收

每个 Release 都应从空白测试库完成一次：

1. BRAT 添加仓库；
2. 启用插件；
3. 安装运行时；
4. 环境自检；
5. 兼容模式导出烟雾测试；
6. 严格模式导出一条真实 Zotero 引用；
7. Word 中刷新；
8. 更新到下一测试版本并确认模板未被覆盖。
